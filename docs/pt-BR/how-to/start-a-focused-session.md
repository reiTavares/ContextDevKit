# Iniciar trabalho focado

Conversa e exploração não precisam iniciar uma sessão governada. Use uma sessão focada quando houver mutação real com objetivo claro.

## 1. Defina o objetivo

```bash
node cdx.mjs dev-start "<objetivo>"
```

ou use a superfície equivalente do host.

## 2. Resolva trabalho existente antes de criar novo

Quando houver evidência de task/Workflow pendente relacionada, prefira retomar. Ambiguidade deve gerar uma pergunta curta, não criação automática.

## 3. Carregue o contexto necessário

Para Workflow, leia PRD, SPEC, decisões, tasks, state e reports relevantes antes de escrever. Para uma mudança direct pequena, não fabrique um pacote durável sem necessidade.

## 4. Execute proporcionalmente

Use especialistas, graph, simulations e outras ferramentas quando adicionarem valor. A ausência deles não bloqueia uma implementação autorizada pelo owner.

## 5. Termine com evidência

Registre testes, findings relevantes, decisões e próximo passo quando houver valor durável.
